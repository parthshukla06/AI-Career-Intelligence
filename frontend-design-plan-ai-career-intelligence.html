Frontend Design Plan

AI Career Intelligence Platform — React + TypeScript frontend. No files created. Awaiting approval.

1. Recommended Technology Stack

Core
  • React 18 UI library
  • TypeScript 5 type safety
  • Vite 5 dev server + bundler
  • React Router v6 client routing
Styling
  • Tailwind CSS v3 utility-first
  • shadcn/ui accessible headless components
  • lucide-react icon set
  • clsx + tailwind-merge class helpers
Data & State
  • TanStack Query v5 server state + caching
  • Zustand lightweight client state (auth)
  • Axios HTTP client with interceptors
  • react-hook-form + zod forms + validation
DX & Quality
  • ESLint + Prettier linting & formatting
  • Vitest + React Testing Library
  • react-pdf in-browser PDF preview
  • recharts skill-gap & readiness charts

Why this stack? Vite gives instant HMR. Tailwind + shadcn avoids a heavy component framework while keeping full design control. TanStack Query handles all API caching/loading/error states, eliminating the need for complex Redux slices. Zustand holds only auth token + user. Zod reuses the same schema shapes as the backend.

5. API Integration Strategy

5a. Axios client (src/api/client.ts)

  • Base URL from VITE_API_URL env var (defaults to http://localhost:5000).
  • Request interceptor reads JWT from Zustand store and attaches Authorization: Bearer <token>.
  • Response interceptor catches 401 → clears auth store → redirects to /login.

5b. TanStack Query hooks (per resource file)

  • Every API call becomes a typed useQuery or useMutation. Loading/error states are handled at component level via skeleton or error card.
  • Query keys follow the pattern ["jobs", filters], ["recommendations", resumeId], etc. to enable targeted cache invalidation.
  • Resume upload is a useMutation with onSuccess setting resumeId in Zustand and invalidating dependent queries.

5c. Exact response envelope

All backend responses follow { success: boolean, data?: T, message?: string, count?: number }. A shared ApiResponse<T> TypeScript type wraps every endpoint's return type.

5d. No invented endpoints

The frontend only calls endpoints confirmed in the backend codebase. Personalized variants are only invoked when a JWT token is present in the store.

6. Authentication Strategy

ConcernImplementation
Token storagelocalStorage — persisted across page refreshes. The token never touches React state directly; Zustand reads it from storage on hydration.
Auth store (Zustand)Fields: token: string | null, user: { id, name, email } | null, resumeId: string | null. Actions: login(), logout(), setResumeId().
Login / Register flowForm → POST /api/auth/login (or /register) → on success store token + user → redirect to /dashboard.
Protected routes<ProtectedRoute /> wraps any route requiring auth. Reads from Zustand; unauthenticated → <Navigate to="/login" replace />.
Axios interceptorAttaches Bearer token automatically to every request when token exists. 401 responses auto-logout.
RehydrationOn app mount, if token exists in localStorage, fetch GET /api/auth/me to verify it is still valid; on failure, clear storage and redirect.
Resume contextAfter a successful upload the returned resumeId is stored in Zustand + localStorage. All intelligence and assistant pages read this as their default input.

7. State Management Approach

State typeToolWhy
Auth token, current user, current resumeIdZustand + localStorageTiny, synchronous, persisted — no need for a full store
Server data (jobs, recommendations, career, dashboard…)TanStack QueryAutomatic caching, background refetch, loading/error states, deduplication
Form state (login, register, career-goal, learning progress)react-hook-formUncontrolled forms with Zod validation, zero re-renders on change
Transient UI state (filter panel open, modal open, chat input)local useStateComponent-scoped; no need to share
What-if skill chipslocal useStateSimple array, no persistence needed

There is intentionally no Redux or Context API. Zustand replaces the tiny global auth slice; TanStack Query replaces all server-data reducers.

8. Step-by-Step Implementation Plan

1
Scaffold the Vite + React + TypeScript project
  • Create frontend/ via npm create vite@latest frontend -- --template react-ts
  • Install all dependencies (Tailwind, shadcn CLI, TanStack Query, Zustand, Axios, react-hook-form, Zod, react-router-dom, lucide-react, recharts)
  • Configure Tailwind, ESLint, Prettier, tsconfig.json, vite.config.ts
  • Add .env and .env.example with VITE_API_URL
  • Update root docker-compose.yml to optionally include a frontend service
2
API layer + TypeScript types
  • Write src/api/client.ts with Axios instance, request interceptor (Bearer token), response interceptor (401 → logout)
  • Define all TypeScript types in src/types/ matching exact backend response shapes
  • Implement all API module files (auth.api.ts, jobs.api.ts, resumes.api.ts, recommendations.api.ts, career.api.ts, assistant.api.ts, user.api.ts)
3
Auth store + routing skeleton
  • Create Zustand store with token, user, resumeId persisted to localStorage
  • Build App.tsx with React Router v6: all routes, ProtectedRoute wrapper, QueryClientProvider
  • Add startup GET /api/auth/me rehydration check in App.tsx
4
Layout shell + shared UI primitives
  • Build AppShell, Sidebar, TopBar, MobileNav (fully responsive)
  • Add shadcn primitives: Button, Input, Badge, Card, Skeleton, Toast, Dialog, Select, Tabs, Tooltip
  • Build EmptyState and ErrorBoundary shared components
5
Landing, Login, Register pages
  • Landing: hero with CTA to upload resume or browse jobs (no auth required)
  • Login/Register: react-hook-form + Zod validation, calls /api/auth/login and /api/auth/register, stores token on success
6
Resume Upload page
  • ResumeUploader component: drag-and-drop + click, PDF-only, ≤ 5 MB, multipart form-data to POST /api/resumes/upload
  • On success: store resumeId in Zustand, display parsed CandidateProfileCard
  • Error states: configuration error (503), provider error (502), oversized (413), invalid type (400)
7
Jobs Board + Job Detail pages
  • Jobs page: JobFilters sidebar + JobCard grid, calls GET /api/jobs with query params
  • Job Detail page: full detail panel, save/unsave button (auth), feedback buttons (auth), apply tracker (auth)
  • Debounced filter inputs, skeleton loading state
8
Recommendations page
  • Requires resumeId — if absent, prompt user to upload resume first
  • Uses personalized endpoint if authed, anonymous otherwise
  • Each RecommendationCard shows overall score + MatchScoreBar, matched skills, missing skills, experience assessment
  • Save-job and feedback buttons visible when authed
9
Career Intelligence pages
  • Career Overview: ReadinessGauge + top recommendations + experience category tabs
  • Skill Gaps: SkillGapList grouped by priority; shows learning progress overlay when authed
  • What-If Simulator: chip input for skill names → calls /api/career/what-if/:resumeId?skills=… → before/after table
  • Skill Demand: SkillDemandChart from GET /api/career/skill-demand (no resumeId needed)
10
Career Assistant page
  • Full-height ChatWindow: free-text chat → POST /api/career-assistant/chat with optional resumeId
  • Sidebar tabs: Chat, Roadmap (RoadmapTimeline), Resume Improvement, Career Paths (CareerPathCard)
  • Sources accordion shows knowledge-base citations returned by the backend
11
Dashboard (auth-gated)
  • StatsRow with saved jobs, applications, readiness score from GET /api/users/me/dashboard
  • Tabs: Overview, Saved Jobs, Applications (ApplicationKanban), Learning Progress
  • Application status updates via PATCH /api/users/me/applications/:jobId
  • Learning progress rows with status dropdown + progress slider → PATCH /api/users/me/learning-progress/:skill
12
Profile / Preferences page (auth-gated)
  • Displays current user info from GET /api/auth/me
  • Edit form for career-goal, targetRoles, preferredIndustries, preferredWorkModes, preferredLocations, experienceLevel, learningGoals, resumeId
  • Saves via PATCH /api/users/me/career-goal
13
Responsiveness, polish, and accessibility
  • Mobile-first Tailwind breakpoints: single-column on sm, 2-col grid on md, sidebar on lg
  • ARIA labels, keyboard navigation, focus rings on all interactive elements
  • Toast notifications for save/unsave, feedback, applications, and errors
  • Dark-mode-ready color tokens in Tailwind config (light mode only initially)
14
Docker + environment config
  • Add frontend/Dockerfile: multi-stage Vite build → nginx serve
  • Update root docker-compose.yml to add optional frontend service on port 3000
  • VITE_API_URL injected at build time via Compose environment
